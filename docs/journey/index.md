# Choose your depth

The Butler documentation is meant to be read in layers.

You do not need to understand Midgard routing contracts before deciding whether
the Butler idea is useful to you.

<div class="grid cards" markdown>

-   **1 · Discover**

    Understand the promise: talk to your home through a Butler, and ask for an
    outcome instead of operating infrastructure.

    [Meet Butler](../meet/index.md)

-   **2 · Understand**

    Learn capabilities, ownership, deterministic-first behavior, verification
    and why the Butler does not replace Home Assistant.

    [Fundamental Concepts](../meet/fundamentals.md)

-   **3 · Install**

    Put a public Butler in your own home, starting from Wilfred and adding only
    the integrations you actually need.

    [Install a Butler](../install/index.md)

-   **4 · Build**

    Architecture, Bifröst, Midgard, Asgard, HAP, APIs, boundaries and proven
    compatibility.

    [Technical Documentation](../documentation/index.md)

-   **5 · Deep Dive**

    ADRs, history, GitHub issue lineage, engineering lessons, experiments and
    the strange ideas at the edge of the project.

    [Explore](../explore/index.md)

</div>

## You can enter from anywhere

These levels are guidance, not prerequisites.

A developer can jump straight to the API.

Someone evaluating the project can live almost entirely in Portfolio.

Someone curious about how the architecture evolved can start from History.

The important part is that increasing technical depth should be available
without being mandatory.
